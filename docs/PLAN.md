# 全体計画(Claude Code 実装用の入口)

このリポジトリは Cicac 乗合タクシー(MITT)パンフレットを Figma MCP で作る Claude スキル `figma-pamphlet` の改修プロジェクト。
オペレータ(非エンジニア、70代読者向け冊子を作る)が使うスキルを「壊れないが平凡」から「初見で『おっ』と言わせる完成度70%の初稿」に引き上げる。

## 最初に読む順番

1. `CLAUDE.md`(リポジトリ直下) — 禁止事項と作業ルール(短い)
2. `docs/context/session-digest.md` — これまでの決定・却下・技術制約の要約
3. `docs/plan/plan-v5.1.md` — 計画書本体。第I部「目指すもの」(モードO/Dの作成フロー、完成形の仕様)、第II部「そのために行うこと」(改修と段取り)
4. `docs/prep/physical-size.md` と `docs/prep/README.md` — 実測から分かった物理サイズ・面表・フォント・色(数値の出典)
5. 担当タスクの指示書 `docs/briefs/*.md`
6. `skill/SKILL.md` と `skill/references/*.md` — 現行スキル(改修対象)

生ログ `docs/context/session-2026-09-26.jsonl` は必要なときだけ grep する(8.6MB)。

## 目指すもの(1分版)

- 表紙の絵(キービジュアル)はデザイン担当(モードD、当面 Hiro)が Nano Banana Pro で先に作ってライブラリ化し、オペレータ(モードO)は番号で選ぶだけ
- 表紙だけ構図プリセット(K1〜K3)を選べる。初版は K2(上ビジュアル+下情報)×H1 のみ
- 採用した絵の見た目は tone.json(色 hex・書体・装飾・構図パラメータ)として同梱し、スキルはそれに従って Figma を操作する
- 検査は二層: 第1層 = コード(preflight.js)が印刷・可読性を Pass/Fail、第2層 = 執筆側と独立した LLM 評価者がルーブリック採点(モードO では納品前に走らせず、デザイン担当の事後QA)
- 入稿は 3mm 塗り足し付きラッパーを rescale して PDF(303×426mm)

## 物理的な前提(必ず守る)

- シート A3(1691×2392px = 297×420mm)。横半分折り+巻き三つ折り → 片面6面(1面 563.7×1196px = 99×210mm)
- 折り線 x=563.7 / 1127.3、y=1196。k = 5.69 px/mm、1pt = 2.01px、3mm = 17px、8mm = 46px、12pt = 24px
- 表紙面(表1)= 表紙フレーム右上の1面。K2 ヒーロー = 表紙面の上55〜60%、塗り足しは上・右
- 逆さ面(下段180°)あり: あいとま 18:2 / 那智勝浦 20:2 / 登別 21:2。下段正立: MITT 24:2。グリーン系は対象外
- Figma は複製ファイル `09Js7rndbabLAoCchqzX9j` だけ。本番 `5qm3YRTEUDdb9RxFUI7ECL` は触らない

## Claude Code での進め方

- タスクごとに別ターミナル(または worktree)で `claude` を起動し、最初に「`CLAUDE.md` と `docs/PLAN.md` と担当の `docs/briefs/<task>.md` を読んでから着手」と指示する
- 成果物は指示書に書かれたパスへ。作業メモ・実行結果は `docs/reports/<task>-*.md` に残す(次の担当者が読む)
- 決めたこと・見つけた制約は `docs/decisions.md` に1行追記。タスクの状態は `docs/tasks.md` を更新
- コミットは小さく、メッセージは日本語可。作者設定は済み(`hiro1117` + Co-Authored-By)
- Figma に書き込む作業(B.1 の実施、C の投入)は、必要なときに複製ファイルに**作業用ページを作って**複製してから行い、原本のテンプレートページは検証が済むまで触らない
- 計画書(Claude Doc)の更新はオーケストレーションセッション側で行う。ここでは `docs/plan/plan-v5.1.md` を「読む」だけにし、変更提案は `docs/reports/` に書く
