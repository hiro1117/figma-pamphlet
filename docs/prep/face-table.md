## 1. 逆さ面(表4側)の実装方式 — 実測結論

1. **面単位の子グループは存在する**(名前 `面:〜(逆さ面)`)。ただし **回転は「面グループ全体の回転」ではなく、葉ノード(テキスト・矩形・ベクター)個々が 180° 回転**している。Figma のグループは子の座標を親フレーム基準で持つため、`GROUP.rotation` は「全子が180°なら180、混在なら0」と見えるだけ(例: 18:287 フッター=180、750:15 ご利用の流れ=0 だが中のテキスト22件はすべて180)。
2. 逆さ絵を Vector で描き直している箇所は**なし**(テキストは全部 TEXT ノードのまま。`textAbsRotHist` で逆さ面のTEXTは全件180、正立面は全件0)。
3. あいとま系表紙 18:2 だけは **フレームそのものがキャンバス上で180°回転**して置かれている。ローカル設計は 20:2/21:2 と同一(上半分=表紙+サービス紹介が正立、下半分=逆さ面)。そのため **キャンバスや get_screenshot では 18:2 は「逆さ面が上・正立、表紙が下・逆さ」に見える**(shots/shot_18-2_canvas.png)。
4. MITT系表紙 24:2 は逆さ面を持たない(下半分「面:使い方面(下)」のTEXT 39件すべて rot 0)。6面(3列×2段、各563×1196)の巻き三つ折り構成(中面 48:513 に「ガイド:面付け枠(6面)」あり)。
5. 中面4種・乗降スポット表に逆さ面はない。
6. 逆さ面のブロック内で **回転していない例外**: 20:2 の `#QR置き場` 20:6(1340,2138 / rot 0、しかも「装飾:背景(逆さ面)」グループの直下=面グループの外)。

## 2. 表4(逆さ面)の正立スクリーンショットの取り方(提案)

前提: 面ノード(GROUP)は9フレームすべてに存在し ID で直接 `get_screenshot` できる(検証済み: 756:20 を撮ると 1073×1007 の逆さ画像が返る。`original_width/height` は面グループのbbox)。

- **A. 面ノードがある場合(本テンプレート全部)**: `get_screenshot(nodeId=面グループid)` → 逆さのPNG → ローカルで180°回転(PIL: `Image.open(p).rotate(180)`)。読み取りだけで済む。検証結果: shots/shot_756-20_canvas.png(撮影そのまま) と shots/shot_756-20_rot180.png(回転後、正立で読める)。
  - 18:2(フレーム自体が180°)は例外で、**逆さ面グループを撮るとそのまま正立**、逆に表紙面 749:6 / サービス紹介面 750:8 を撮ると逆さになる → こちらを180°回す。
  - 3グループ(ご利用の流れ・料金運行・フッター)を個別に撮るか、下半分をまとめて見たいときは「装飾:背景(逆さ面)」ではなく面グループ3つを撮って並べる(下半分だけを1ノードで表す親はない)。
- **B. 面ノードがない場合(制作物ページの旧世代複製など、例: テスト_真四角町の 664:3 は「サービス紹介面(見出し・本文エリア)」等の旧名)**: フレーム全体を撮って画像を上下で切り、下半分を180°回転する(縦型: y=1196で分割。18:2 系の複製は上半分が逆さ面)。
- **C. 書き込みを伴う方法(今回は不使用)**: clone → rotation を 180 → screenshot → remove。原本には触れないこと。
- 補足: `get_screenshot` の画像URL(figma.com)は本環境のプロキシでブロックされるため、`enableBase64Response:true` で受け取る(tool-results にPNGが保存される)。
