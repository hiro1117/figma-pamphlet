# 指示書 B.1: 表紙フレームの改修(4系統)

## 目的
表紙テンプレート4系統(あいとま 18:2 / 那智勝浦 20:2 / 登別 21:2 / MITT 24:2)を、キービジュアル・ライブラリと tone.json が「差し替えるだけ」で効く構造にする。二段階で進める: **(1) 設計**(読み取りのみ、変更一覧を書く)→ Hiro のレビュー → **(2) 実施**(作業用ページに複製して改修、検証後に原本と差し替え)。

## 先に読むもの(順番)
1. `CLAUDE.md`, `docs/PLAN.md`
2. `docs/prep/physical-size.md`、`docs/prep/face-table.md`(各表紙の面構成・直下の子・回転)、`docs/prep/text-inventory.md`(TEXT の実名とサイズ)、`docs/prep/image-inventory.json`(`#〇〇置き場`と imageHash)、`docs/prep/colors.md`、`docs/prep/file-facts.md`(凡例フレーム 599:2 の命名規約全文)
3. `docs/plan/plan-v5.1.md` の 6.1(ヒーローの層構造)、6.3(編集区分・プリセット・装飾の配置規則)、B 章(B.1)、D.2(変換表: 改修後にスキルがどう操作するか)
4. Figma の `figma-use` スキル

## 前提(数値)
- 表紙面(表1)= 各表紙フレームの右上1面: ローカル座標 x 1127.3〜1691、y 0〜1196(563.7×1196px = 99×210mm)。左辺(x=1127.3)と下辺(y=1196)は折り線、上辺と右辺は仕上がり端
- K2 ヒーロー枠 `#キービジュアル`: 表紙面の上 55〜60%(高さ 658〜718px)、幅は表紙面いっぱい。塗り足しとして上へ 17px・右へ 17px はみ出す(フレーム外に出るので制作物フレームは clipsContent=false)。左・下は折り線なので塗り足しなし。scaleMode は CROP
- 折り線からの安全域: 文字 46px(8mm)、装飾 17px(3mm)。端ピタ禁止(仕上がり端から 17px 内側か、17px 外側まで延長)
- あいとま 18:2 はフレーム自体が180°回転して置かれている(ローカル設計は 20:2/21:2 と同じ)。ローカル座標で設計し、絶対座標は回転を考慮
- MITT 24:2 は下段正立。表紙面(右上 763:2)の高さが 1216 で折り線を 20px 越えている(修正候補)

## 成果物
### (1) 設計(先にここまでやって Hiro に見せる)
- `docs/reports/B1-cover-refit-design.md` — 系統ごとに: (a) 命名変更の一覧(現ノード id・現名 → 新名。`#本文` `#注記` `#見出し` `#電話` `#CTA` `#QR` `#バッジ` `#AI表記`。既存規約 `#`=差し替え可 と接頭辞に整合させ、既存の `#〇〇置き場` は残す) (b) 追加ノードの仕様(`#キービジュアル`(K2枠、位置・サイズ・塗り足し・CROP)、`#地域モチーフ`(hero_horizon 帯: ヒーロー枠内の地平線帯、人物・車両より背面)、`#人物` `#車両`(FIT、ヒーロー枠内の最前面)、`#帯` `#背景`(非表示の空プレースホルダ)、`#AI表記`(発行者情報欄の固定文)、`テンプレート`ページの `#config` 非表示テキスト) (c) ヒーロー枠に重なる既存要素(イラスト・写真置き場・タイトル)の扱い(隠す/移す/残す) (d) 12pt 未満の文字を #000000 に統一する対象一覧 (e) 各変更が 6.3 の配置規則(折り線・端ピタ)を満たすことの確認 (f) 検証方法(改修後のスクショ、P5/P6 相当の幾何チェック)
- `docs/reports/B1-refit-plan.json` — 上記を機械可読に(系統 → 変更配列 {op: rename|create|hide|move|setFill, target, params})
- 各表紙の現状スクショに K2 ヒーロー枠と折り線を重ねた画像(`docs/reports/B1-shots/`)。get_screenshot は `enableBase64Response:true`、重ね描きは PIL

### (2) 実施(Hiro の OK 後)
- 複製ファイルにページ `テンプレ改修_作業` を作り、4表紙を clone してそこで改修。原本は触らない
- 改修は use_figma を系統ごと・工程ごとに分け、各呼び出しで created/mutated の node id を返す(retry-safe に)
- 完了後: `docs/reports/B1-after/` にスクショ、改修後の `#` ノード一覧(id・名前・位置)と imageHash を `docs/prep/template-refit-inventory.json` に保存
- 原本との差し替え(テンプレートページへの反映)は Hiro の確認後に行う

## 禁止・注意
- 本番ファイルに触らない。テンプレート原本・参照ページを直接編集しない
- 新規ノードは最小限。装飾は「空プレースホルダを置く」だけで、見た目の変更(色・書体)はしない(それは tone.json とスキルの仕事)
- フォントを触るときは `loadFontAsync` を先に。欠落フォントのノードは名前変更のみ(文字は触らない)
- 命名は凡例の規約に合わせ、`#〇〇置き場` など既存名で他資料が参照しているものは変えない(変える場合は変換表 D.2 と整合させて報告)

## 受け入れ条件
- 設計書に4系統すべての変更一覧・ヒーロー枠の座標・重なりの処置が書かれ、K2 枠が「表紙面の上55〜60%、上・右のみ塗り足し」を満たす
- 実施後、`#キービジュアル` に任意の画像 hash を CROP で入れて折り線・仕上がり端の幾何が P5/P6 相当のチェックを通る
- 表4側(逆さ面)と中面は変更していない
- `docs/tasks.md` の B.1 を更新、決めたことを `docs/decisions.md` に追記
