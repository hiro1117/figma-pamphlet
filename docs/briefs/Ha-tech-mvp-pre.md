## 作業

作業場所は作業用ページ「テンプレ改修_作業」(2053:2、現在は空)。テンプレート 0:1・参照 6:2・制作物 7:2・素材ページのライブラリ原本は編集しない(clone して使う)。

1. 2053:3 と 47:2 を作業用ページに clone し、`くらぶちMVP_表紙` `くらぶちMVP_中面` とする
2. くらぶち 71:2 / 71:271 の文言を `#` スロットに流し込む(テンプレに無い要素は流し込まず、差分を記録する)
3. D.2 の変換表に沿って手で適用: 色(palette)、見出し(H1)、`#キービジュアル`(背景を CROP)、`#地域モチーフ`(榛名山、hero_horizon)、`#人物` `#車両`(FIT、library-v0.json の layout_rule)、`#帯` `#背景`、`#AI表記`。中面は第1段の範囲(色置換)のみ
4. preflight を表紙・中面に実行 → Fail を直す → 再実行(最大3周)。直せない Fail は理由を記録
5. D.3 のラッパー: `書き出し` ページ(無ければ作る)に 1725.2×2426.2 のラッパーを作り、`rescale(0.497865)` → P1 を確認。PDF の Export は Hiro が行う(手順を報告に書く)
6. 第2層の試走: 執筆側の経緯を渡さないサブエージェントに、表1の正立スクショ(長辺 1568px)と 6.5 のルーブリックを渡して採点させる(未較正なので数値は参考。「プロの AD なら直す点3つ」を重視)
7. 改修前(制作物のくらぶち 71:2)と MVP 表紙を並べたスクショを作る

## 測るもの(計画書 H(a) の項目)

- 第1層の誤検知(Fail/Warn のうち実害なしと判断したもの)の件数と内訳
- 装飾・プレースホルダの折り線侵犯 0 件か
- 層構造: 人物の顔・車両がモチーフやタイトルに隠れず枠内に残るか、人物が表1ビジュアルの 1/3 以上か(K2 枠比率と CROP の検証)
- タイトル・CTA がヒーローの上で読めるか(白フチ・コントラスト)
- 実効 dpi(P13 の式)、ラッパーの寸法
- 手作業のうち D で自動化すべき操作と、変換表 D.2 に無かった・合わなかった操作
- 所要(use_figma の呼び出し回数でよい)
