# Figmaパンフレット作成スキル

スキル版: 2026-08-20

Figma MCPでパンフレットの叩き台を作り、対話で調整し、細部は人の手作業に引き渡す。利用者は非エンジニア。専門用語(ノード、API、JSON等)を使わずに案内する。

パンフレットの目的は固定: **MITT(配車アプリ)導入地域の住民へのサービス紹介と、登録・利用方法の案内**。ゴール行動は「登録・予約して使い始めてもらう」(LINE登録または電話予約)なので、ヒアリングでは聞かず、CTAは掲載内容の予約方法に合わせて作る。

## 参照ファイル

- `references/figma-ops.md` — **use_figmaを呼ぶ前に必ず読む。** フォント読み込み・色指定など、読まないと失敗する操作ルール
- `references/template-and-assets.md` — テンプレート複製とイラスト受け渡しの手順。Step 2以降で読む
- `references/design-rules.md` — デザイン表現・可読性・削る優先順位。デザイン判断に迷ったら読む

## Step 0: 前提確認

1. Figma MCPのツール(use_figma / get_metadata / get_screenshot)が使えるか確認する。使えなければ、Figmaコネクタの有効化を案内して止まる
2. 作業対象のFigmaファイルを決める。利用者がURLを指定していればそれを使い、指定がなければtemplate-and-assets.mdの「現在の作業対象」を使う。**どちらの場合も、キャンバスに書き込む前に「対象ファイル: 〈ファイル名〉(〈URL〉)で作業します。よろしいですか?」と1行で確認する**(別ファイルを操作する事故を防ぐため。以後の報告にもファイル名を添える)

## Step 1: ヒアリング

以下が揃うまでキャンバスに書き込まない。会話・添付から拾えるものは先に埋めて「こう理解しました」と提示し、不足分だけを1回のメッセージで聞く。

1. **案件情報** — 地域名・自治体/事業者名・サービス名称(「〇〇号」等の正式表記)。複製フレーム名と紙面の表記に使う
2. **作るもの** — 冊子(表紙+中面)か単票か。冊子の場合は「乗降スポットの一覧表は載せますか?」もあわせて確認
3. **載せる内容** — 文言の素材。なければ草案を作って確認を取る
4. **イラスト・写真** — 利用者が商用利用可のサイトから選び、`素材`ページに案件ごとのグループとして置く。**そのグループのURLを独立した項目として確認する**(受け渡し手順はtemplate-and-assets.md)
5. **カラー** — 「指定の色(自治体・事業者のブランドカラー等)はありますか?なければこちらから提案します」。ロゴや既存媒体があれば共有してもらい色を拾う

## Step 1.5: カラー決定

キャンバスに書き込む前に色を確定させる。指定色があればメイン色として「この色の濃淡で作ります」と宣言。未定なら、題材・地域のイメージからカラー2〜3案の見本チップを制作物ページに生成し、スクリーンショットで選んでもらう(手順と各テンプレートの色対応表はtemplate-and-assets.md「カラーの適用」)。

## Step 2: テンプレート複製

複製の前に`制作物`ページを確認し、同じ案件のフレームが既にあれば新規複製せず既存の続きから作業する(「前回の続きから再開します」と伝える。重複フレームがあればどれを正とするか利用者に確認し、勝手に削除しない)。

ゼロから描かず、テンプレートを複製してから編集する(毎回ゼロから作るとデザインがぶれるため)。冊子は**表紙+中面を必ずセットで複製**し、乗降スポット表はヒアリング2で「あり」の場合のみ追加で複製する。作業順序は **複製→カラー適用→文言→素材**(文言を入れた後の色替えは確認のやり直しになるため)。適合テンプレートがない場合のみ新規で組み、既存の完成見本をget_screenshotで見てトーンを合わせる。

## Step 3: 文言・素材の差し替え

1ブロック(見出し→本文→素材…)ずつ操作し、都度成功を確認する。テキストはフォント読み込みの定型(figma-ops.md)に従う。イラストは「素材」ページから(指示があれば既存テンプレートのイラストも)複製して配置する。**共有された素材は原則すべて使う**(使い残す場合は理由を添えて確認を取る。詳細はtemplate-and-assets.md)。

## Step 4: スクリーンショット確認と対話調整

1. get_screenshotで現状を取得し、文字あふれ・重なり・余白潰れを自分の目で確認する。崩れは利用者に見せる前に直す
2. 画像を見せて修正点を聞く。曖昧な指示は汲み取る(「もっと目立たせて」→サイズ・色・位置の案を提示)。「文字を大きく」等の読みやすさの調整もここで対話的に行う
3. 調整のたびに変更箇所を1〜2文で報告する
4. 同じ箇所に3回以上修正が入る、または数ピクセル単位の微調整を求められたら、手作業への切り替えを提案する

## Step 5: 手作業への引き渡し

終了時に必ず伝える:

- 作成・変更したフレーム名と場所
- 未完了・要確認の箇所(仮置き文言、未確認の電話番号・QR等)
- Figma上で自分で微調整するヒント(例:「文字はダブルクリックで直接編集できます」)

## 完了前チェック

「完成」報告の前にget_screenshotで最終確認し、○/✗で報告する:

- [ ] フレーム寸法が基準寸法と一致している(入稿データ。template-and-assets.md「入稿データの厳守」)
- [ ] 文字あふれ・要素の重なり・はみ出しがない
- [ ] キャッチコピーが最も目立ち、CTAが明記されている
- [ ] 仮置きテキスト・ダミー文言が残っていない
- [ ] 固有名詞・電話番号に誤りがない
- [ ] 可読性基準(design-rules.md)を満たす
