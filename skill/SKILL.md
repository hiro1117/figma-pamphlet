# Figmaパンフレット作成スキル

スキル版: 2026-10

Figma MCPでパンフレットの初稿を作り、対話で調整し、細部は人の手作業に引き渡す。利用者(オペレータ)は非エンジニア。**専門用語(ノード、API、JSON、tone、preflight、スコア等)を使わずに案内する。「不合格」「点数」は出さない。** オペレータが行うのは「番号で選ぶ」「はい」「書き出し」だけで、画面外の操作は「写真の貼り込み(あれば)」と「Export」の2回に収める。

パンフレットの目的は固定: **MITT(配車アプリ)導入地域の住民へのサービス紹介と、登録・利用方法の案内**。ゴール行動は「登録・予約して使い始めてもらう」(LINE登録または電話予約)なので、ヒアリングでは聞かず、CTAは掲載内容の予約方法に合わせて作る。

## 参照ファイル

- `references/figma-ops.md` — **use_figmaを呼ぶ前に必ず読む。** フォント読み込み・色指定・`#config`/`#tone`/`#state` の読み書き・スタイルタイルのスクリプト
- `references/template-and-assets.md` — テンプレートの id 表、面と折り線、編集区分、`#` 命名、フォント許可リスト、色の置換、素材の受け渡し、入稿寸法。Step 1.5 以降で読む
- `references/preflight.md` — 印刷・読みやすさの自動チェック(第1層)の仕様とスクリプト全文。Step 4 で読む
- `references/keyvisual.md` — 表紙の絵(キービジュアル)ライブラリの作り方と運用(デザイン担当向け。オペレータの案件では読まなくてよい)
- `references/evaluator.md` — 見た目の採点(第2層、デザイン担当の事後確認用)。オペレータの案件では使わない
- `references/design-rules.md` — デザイン表現・可読性・削る優先順位。デザイン判断に迷ったら読む
- `references/legacy-2026-08-20.md` — `pipeline: off` のときの旧手順
- `scripts/*.js` — use_figma にそのまま貼るスクリプト。**先頭の `CONFIG` だけを書き換えて使う**(本体は書き換えない)。`fill-text.js`(書体と文言)・`place-images.js`(絵と画像)・`recolor.js`(色)・`preflight.js`(自動チェック)・`autofix.js`(自動修正)・`wrapper.js`(書き出し用の枠)

## Step 0: 前提確認(版と切り替えスイッチ)

1. Figma MCPのツール(use_figma / get_metadata / get_screenshot)が使えるか確認する。使えなければ、Figmaコネクタの有効化を案内して止まる
2. 作業対象のFigmaファイルを決める。利用者がURLを指定していればそれを使い、指定がなければtemplate-and-assets.mdの「現在の作業対象」を使う。**どちらの場合も、キャンバスに書き込む前に「対象ファイル: 〈ファイル名〉(〈URL〉)で作業します。よろしいですか?」と1行で確認する**(別ファイルを操作する事故を防ぐため。以後の報告にもファイル名を添える)
3. `テンプレート`ページ直下の非表示テキスト `#config` を読む(figma-ops.md「#config を読む」)。オペレータには結果だけを短く伝え、中身は見せない
   - `skill_min_version` がこのスキルの版(上の「スキル版」)より新しい → **ここで止まる**。「このスキルは古い版です。リーダーに最新版への更新を頼んでください」とだけ伝える
   - `pipeline: "off"`、`#config` が見つからない、または読めない → `references/legacy-2026-08-20.md` の手順で進める(オペレータには「今回はこれまでの作り方で進めます」とだけ伝える)
   - `pipeline: "on"` → 以下の Step 1〜5
4. `制作物`ページに同じ案件のフレームがあり、その表紙直下に `#state` があれば、そこに書かれた Step から再開する(「前回の続きから再開します」と伝える。figma-ops.md「#state」)

## Step 1: ヒアリング

以下が揃うまでキャンバスに書き込まない。依頼文や会話・添付から拾えるものは先に埋めて「こう理解しました」と提示し、不足分だけを1回のメッセージで聞く。**依頼票(`pamphlet-brief` スキルが仕様書から作る `〈案件名〉_依頼票_〈日付〉.json`)が添付されていれば最初に読む**: `status` が `確定` `予定` の項目は埋まっているものとして扱い(`予定` は Step 5 の要確認に載せる)、`協議中` `要確認` `推測` `草案` の項目と `open_questions` の `blocking: true` だけを聞く。項目の対応は依頼票側の `references/schema.md` §9。**着手できるかどうかは申告では決めず、Step 1.5 のゲートで確かめる**(「絵は準備できていますか?」とは聞かない)。

1. **案件情報** — 地域名・自治体/事業者名・サービス名称(「〇〇号」等の正式表記)。フレーム名・紙面の表記・素材ページの案件グループ名(`案件/<案件名>`)に使う
2. **作るもの** — 冊子(表紙+中面)か単票か。冊子の場合は「乗降スポットの一覧表は載せますか?」もあわせて確認
3. **載せる内容** — 文言の素材。なければ草案を作って確認を取る
4. **ロゴ・QR・地図・写真(実車・実風景)があれば** — 素材ページの `案件/<案件名>` のグループに入れてもらう(地域の絵と同じ場所)。イラストはこちらで用意した絵を使うので持ち込まない(template-and-assets.md「素材の受け渡し」)。地図は乗降スポットの印(ピン)を描き込んだ画像にしてもらう(テンプレに地図ピンの部品は無い)
5. **色の指定** — 「自治体・事業者のブランドカラーなどの指定はありますか?」。なければ Step 1.5 で選ぶ絵の色で作る
6. **生成AIで作ったイラストを使ってよいか** — 「表紙の絵は画像生成AIで作ったものです。自治体・事業者の決まりで使えないことはありませんか?」。**使えない場合は Step 1.5 以降に進まず `references/legacy-2026-08-20.md` の手順で作る**
7. **地域名と名所の候補** — 表紙の山や川などの絵(地域の絵)に使う。リーダーが依頼文に書いていればそれを使う

## Step 1.5: 絵の系統と見本を選ぶ(色見本の選択の代わり)

1. **地域の絵の確認(ゲート)**: 素材ページに `案件/<案件名>` のグループがあり、その中に名前が `#地域モチーフ` で始まる絵があるかを確認する(figma-ops.md「地域の絵のゲート」)。**無ければ着手しない。**「この地域の絵がまだ準備されていません。共有チャンネルでデザイン担当に『〈案件名〉の地域の絵をお願いします』と依頼し、用意できたら『続きから』と声をかけてください」と伝えて止まる。他地域の絵では代用しない
2. **系統を選ぶ**: 表紙4系統(template-and-assets.md の表)のスクリーンショットを番号付きで見せて選んでもらう。事業者のブランド指定があれば MITT 系。**あわせて折り方を1行で確認する**: あいとま系・那智勝浦系・登別系は「下の段を逆さに組む折り方」、MITT 系は「下の段も上向きの折り方」。印刷の注文と違えば系統を選び直してもらう
3. **見本を選ぶ**: 選んだ系統の素材ページ `ライブラリ/<系統名>` のグループ(背景・人物・車両が並んだもの)のスクリーンショットを番号付きで見せる。注記「雰囲気の見本です。文字と細かい配置は変わります」を必ず添える
   - 見本が複数あるときは消去法で聞く(まず一番合わないものを外してもらい、残りから選ぶ)。見る観点は3つ: 「この絵の中にうちの地域の利用者がいると感じるか」「70代の親に渡して『いいね』と言われそうか」「うちの地域の地形と暮らし(山あい/海辺/町なか、農作業/買い物/通院)に近いか」
   - 見本が1つだけの系統(2026-10 時点は全系統1つ)は「この見本で進めてよいですか?」と聞く
   - 選んだ理由を一言もらい、そのまま記録する(言い換えない)
   - 「どれも違う」ときは最も近い見本で続け、共有チャンネルに一言報告してもらう
4. **色の指定がある場合**(Step 1 の5): 指定色を「メインの色」に充てる。MITT 系はブランド色が固定なので替えない(「MITT 系は色が決まっているため、指定の色は使えません」と伝える)。濃さの調整は figma-ops.md「指定色の反映」に従う

## Step 1.7: スタイルタイルで確認 → 記録

1. figma-ops.md「スタイルタイル」のスクリプトで、`制作物`ページの空き位置に `〈案件名〉_スタイルタイル_〈日付〉` を1枚作る(色チップ・実際のタイトルを見出しの書体で実寸・電話番号の見本・飾りの有無・表紙の絵の縮小を1枚にまとめたもの)
2. スクリーンショットを見せ、「この雰囲気で作ってよいですか?」と聞く。**見本側で決まっていない項目(標準の値を使っているもの)を1行で添える**(例: 「見出しの書体と構図は標準のものです」)。どれが標準かは記録の `provenance` が `default` の項目で分かる。オペレータへの質問は「はい/いいえ」だけにする
3. 「はい」→ 同じスクリプトが作った非表示の記録(`#tone` = 見た目の方針、`#state` = 進み具合)をタイルの中に残したまま Step 2 へ。「いいえ」→ どこが違うかを一言聞き、Step 1.5 の3からやり直す(不採用のタイルは消す)

## Step 2: テンプレート複製

1. Step 1.5 で選んだ系統の表紙+中面を**必ずセットで**複製し(乗降スポット表はヒアリング2で「あり」の場合のみ)、`制作物`ページへ移して `案件名_表紙/中面/スポット表_日付` に改名する(template-and-assets.md「複製の手順」。構図は `#config` の `cover_preset`(現在 K2B_panel)固定)
2. 複製直後に寸法が基準寸法と一致することを確認する
3. タイルの中の `#tone` と `#state` を**表紙フレームの直下へ移す**(非表示・ロックのまま)。`#state` の `step` を `"2"`、`frames` に複製したフレームの id を書く(figma-ops.md「#state」)。スタイルタイル本体は完了報告まで残す
4. 作業順序は **書体と文言 → 絵と画像 → 色**(Step 3)。色を最後にするのは、流し込みで書式が変わった文字にも置換を効かせるため

## Step 3: 組版(書体・文言 → 絵・画像 → 色)

オペレータには「組んでいます」とだけ伝え、以下を続けて行う。各スクリプトは表紙と中面で呼び出しを分ける(ページの切り替えは 1 回ずつ)。**新しい図形は作らない**(置いてある枠の差し替え・表示の切り替え・大きさの調整だけ)。

1. **書体と文言**(`scripts/fill-text.js`)
   - 文言は原稿から `#<役割>:<スロット名>` の枠ごとに `SLOTS` へ写す(枠の名前は figma-ops.md「探索と返り値の約束」の `{名前 → id[]}` の地図で取る)。表紙の題字 `#見出し:サービス名`(MITT は `#見出し:サービス名1/2`)には案件のサービス名を入れる。あいとま系中面の `#見出し:中面タイトル` には**地名 + 「乗降スポット」**(例「くらぶち 乗降スポット」。サービス名ではない)を入れる。題字・中面タイトルは 2 行にしない。同じ名前の枠が複数あるとき(午前・午後の時間など)は配列で上から順に渡す
   - スクリプトが行うこと: ①環境に無いフォントの置き換え(本文系 → Noto Sans JP の同じ太さ、見出し → 見本の見出し書体、電話・TEL ラベル → 見本の数字書体)を流し込みの前に ②表紙面の `#見出し` を見本の見出し書体に、`#電話` を数字書体に(MITT 系は替えない)③流し込み: 本文・注記は原稿の改行を外して箱の幅で折り返す(見出し・STEP は改行を残す)→ 一時的な複製で高さを測り、足りなければ箱を伸ばす(伸ばすと折り目にかかるなら伸ばさず引き渡し)→ 折り目との距離を確かめる ④電話番号・題字は改行を外して 1 行にし、箱に収まらなければ文字を縮める(自動幅の題字は `MAX_RIGHT` で右隣のロゴを避ける)
   - 回転している面(逆さ面・あいとま系)でも本体の「自動サイズ」は切り替えない。計測は一時的な複製で行い、必ず消す(スクリプトが処理)
   - 書式が途中で変わる枠(一部だけ赤字など)は文言を入れず引き渡しに回る。入れる必要があれば `FORCE_MIXED` を使い、あとで色を当て直す
   - テンプレに枠が無い原稿(料金の補足、QR の説明など)は入れずに引き渡しに載せる
   - 返り値の `handoff` は Step 5 の残指摘にそのまま使う
2. **絵と画像**(`scripts/place-images.js`)
   - 表紙: `#キービジュアル` = ライブラリの背景を切り抜き配置(CROP、切り抜き量は枠と画像の縦横比から計算)、`#人物`(見本で選んだ人物A/B)・`#車両`・`#地域モチーフ` = そのまま収める(FIT)。枠の位置・大きさは `#config` の `presets.K2B_panel.by_family`(系統名で引く)に合わせる
   - 案件の画像(ロゴ・QR・地図・写真)は `EXTRA` で置き場を指定する(`案件/<案件名>` のグループの中身を見て決める。どれをどこに置くか迷ったら1行で確認する)
   - 素材の入らなかった `#…置き場`、`サンプル:` の見本、ロゴ枠の間の「×」は非表示にする。QR や地図を後で人が入れる場合は `KEEP_VISIBLE` に入れて残し、引き渡しに載せる
3. **色**(`scripts/recolor.js`、表紙と中面を 1 回で)
   - テンプレの濃い色・淡い色を見本の「メインの色」「淡い色」に置き換える(系統ごとの対応は template-and-assets.md「カラーの適用」)。写真・イラストの中の色は変わらない
   - 表紙面の電話番号の文字と、CTA 見出しのメイン色の部分を「電話・申込の色」に
   - 白い文字が載っているメイン色のパネル・帯(1面の 20% 以下の大きさ)は「電話・申込の色」に(メイン色のままだと白い文字が読みにくい)
   - 「差し色」は `#バッジ` に当てない(テンプレの色のまま)。MITT 系は色を替えない
4. `get_screenshot` で表紙面(あいとま系は正立に回して見る)と中面を確かめる。題字・電話番号が隣の要素に重なっていないか、人物の顔・車両がロゴや地域の絵に隠れていないかを見る。気になる点は Step 4 の前に直す
5. `#state` の `step` を `"3"` にする

## Step 4: 自動チェック(第1層)と自動修正(2 回まで)

組版が終わったら、オペレータに聞かずに `references/preflight.md` のスクリプトを実行する(テンプレートページでは走らせない)。

1. 呼び出しの分け方: 表紙は1枚ずつ、中面は2枚まで、乗降スポット表は別の呼び出し。互いに独立なので同じメッセージで並べて出す
2. `CONFIG` で書き換えるのは次だけ:
   - `PAGE_ID` = `制作物`ページ、`FRAME_IDS` = 対象フレーム
   - `SHEET` = 冊子の表紙・中面は `'A3_booklet'`、乗降スポット表は `'A4_spot'`(このときは電話番号の大きさの項目は「対象外」になる)
   - `FRAME_KIND` = 表紙 `'cover'`、中面 `'inner'`
   - `FAMILY` = **Step 1.5 で選んだ系統から渡す**(`#tone` の `meta.template_family` を読み、あいとま系 → `'aitoma'`、那智勝浦系 → `'nachikatsuura'`、登別系 → `'noboribetsu'`、MITT 系 → `'MITT'`)。案件のフレーム名からは系統を推定できないため `'auto'` のままにしない
3. 返り値の `tmpRemovedAtEnd` が 0 であることを確認する(一時的に作った計測用の複製が残っていない証拠)
4. **自動修正**(`scripts/autofix.js`): Fail の items(`check` `node` `limit`)を `ITEMS` に写して実行する。直すのは機械的に直せるものだけ:
   - 文字のはみ出し(P3-a)→ 箱の高さを文字に合わせる(伸ばすと面の境目の折り目にかかるなら直さない)
   - 文字が小さい(P2)→ 小さい部分だけ下限の大きさへ上げ、はみ出したら箱の高さも合わせる(注記 9pt・白抜き 12pt など、下限は preflight の `limit`)
   - 折り目に近い(P6)→ 箱が字面より広いだけのときに箱の幅を字面に縮める。字面そのものがかかっているときは直さない
   - 文字と背景の差が足りない(P4)→ 白い文字の下の面がメイン色なら「電話・申込の色」に。それ以外は直さない
   - 寸法(P1)・枠からのはみ出し(P3-b)・仮の文言(P7)・電話番号の大きさ(P12)・その他 → 直さず引き渡し(文言や組みの判断が要る)
   - 修正のあと preflight をもう一度実行する。これを**最大 2 回**。2 回目の後も残る ✗ と、autofix が返した `handoff` を Step 5 の残指摘にする
5. オペレータには**チェック項目ごとに1行の ○/✗/△ だけ**を見せる(最後の preflight の結果)。書き方は preflight.md §6「○/✗/△ 要約の作り方」に従い、複数フレームの結果は項目ごとにまとめる。項目名はやさしい言葉にする(P1 寸法 / P2 文字の大きさ / P3-a 文字のはみ出し / P3-b 枠からのはみ出し / P4 文字と背景の見やすさ / P6 折り目との距離 / P7 仮の文言 / P12 電話番号の大きさ)。△ は「次回改善(このまま印刷に出せます)」または「目で確認」と添える。自動で直したものは「○(自動で直しました)」とだけ言い、中身は言わない。`寸法` が ✗ のときは他を読まずに「寸法が違うので複製からやり直します」を先に出し、Step 2 からやり直す
6. `#state` に `preflight`(フレームごとの fail/warn/manual の件数と実行日時)・`autofix_rounds`・`handoff`(残指摘の一覧)を書き、`step` を `"4"` にする

## Step 5: 書き出し用の枠と引き渡し

1. **書き出し用の枠(ラッパー)を作る**(`scripts/wrapper.js`)。**最後の preflight の後に作る**(ラッパーは複製なので、後で制作物を直したら作り直す。同名は `REPLACE` で置き換わる)
   - 表紙・中面で 1 回ずつ。名前は `案件名_表紙_書き出し_日付` / `案件名_中面_書き出し_日付`、置き場所は `書き出し` ページ(無ければスクリプトが作る)
   - スクリプトが行うこと: 四辺に 3mm(17.08px)足した枠に制作物の複製を入れる → 塗り足しは**端の色を延長**(辺ごとに端の色を調べ、一番長い色を枠の塗りに、それ以外の区間は背面に塗り足しの帯を置く)→ `rescale(0.497865)` → 寸法を確認(縮小前 1725.2×2426.2、縮小後 858.9×1207.9 = 303×426mm。横型の中面は縦横が入れ替わる)
   - 返り値の `p1.beforeOk` `p1.afterOk` が両方 true であること。`unknown`(端が写真・グラデーションの区間)があれば塗り足しが足りないので引き渡しに載せる
2. `#state` の `step` を `"5"` にする
3. 終了時に必ず伝える:
   - 作成・変更したフレーム名と場所(スタイルタイルは不要になったら削除してよいか確認する)
   - 残指摘(Step 3・4 の引き渡し)と、未完了・要確認の箇所(仮置き文言、未確認の電話番号・QR等)
   - **✗ が1つでも残るときは「このままでは印刷に出せません」と明記し、書き出すファイル名の末尾に `_未確認` を付けるよう伝える**(入稿しない。リーダーが直してチェックをやり直し、✗ が 0 になってから入稿する)
   - **PDF の書き出し手順**(オペレータが行う唯一の操作。この文面をそのまま出す):
     1. Figma の左のページ一覧で「書き出し」を開く
     2. 「〈案件名〉_表紙_書き出し_〈日付〉」をクリックして選び、Shift を押しながら「〈案件名〉_中面_書き出し_〈日付〉」もクリックする
     3. 右側のパネルのいちばん下「エクスポート」の「+」を押す
     4. 形式を「PDF」にし、設定(…)で画質を「高」にする
     5. 「エクスポート」を押す。表紙と中面の 2 つの PDF ができる(✗ が残っているときはファイル名の末尾に `_未確認` を付ける)
   - Figma上で自分で微調整するヒント(例:「文字はダブルクリックで直接編集できます。直したら『チェックをやり直して』と声をかけてください」)。制作物を直したら書き出し用の枠は作り直す
