# Figmaパンフレット作成スキル

スキル版: 2026-10(作業中: Step 3 の変換表・Step 4 の自動修正・Step 5 のラッパー自動化は未実装。下記【H の結果待ち】)

Figma MCPでパンフレットの初稿を作り、対話で調整し、細部は人の手作業に引き渡す。利用者(オペレータ)は非エンジニア。**専門用語(ノード、API、JSON、tone、preflight、スコア等)を使わずに案内する。「不合格」「点数」は出さない。** オペレータが行うのは「番号で選ぶ」「はい」「書き出し」だけで、画面外の操作は「写真の貼り込み(あれば)」と「Export」の2回に収める。

パンフレットの目的は固定: **MITT(配車アプリ)導入地域の住民へのサービス紹介と、登録・利用方法の案内**。ゴール行動は「登録・予約して使い始めてもらう」(LINE登録または電話予約)なので、ヒアリングでは聞かず、CTAは掲載内容の予約方法に合わせて作る。

## 参照ファイル

- `references/figma-ops.md` — **use_figmaを呼ぶ前に必ず読む。** フォント読み込み・色指定・`#config`/`#tone`/`#state` の読み書き・スタイルタイルのスクリプト
- `references/template-and-assets.md` — テンプレートの id 表、面と折り線、編集区分、`#` 命名、フォント許可リスト、色の置換、素材の受け渡し、入稿寸法。Step 1.5 以降で読む
- `references/preflight.md` — 印刷・読みやすさの自動チェック(第1層)の仕様とスクリプト全文。Step 4 で読む
- `references/keyvisual.md` — 表紙の絵(キービジュアル)ライブラリの作り方と運用(デザイン担当向け。オペレータの案件では読まなくてよい)
- `references/evaluator.md` — 見た目の採点(第2層、デザイン担当の事後確認用)。オペレータの案件では使わない
- `references/design-rules.md` — デザイン表現・可読性・削る優先順位。デザイン判断に迷ったら読む
- `references/legacy-2026-08-20.md` — `pipeline: off` のときの旧手順

## Step 0: 前提確認(版と切り替えスイッチ)

1. Figma MCPのツール(use_figma / get_metadata / get_screenshot)が使えるか確認する。使えなければ、Figmaコネクタの有効化を案内して止まる
2. 作業対象のFigmaファイルを決める。利用者がURLを指定していればそれを使い、指定がなければtemplate-and-assets.mdの「現在の作業対象」を使う。**どちらの場合も、キャンバスに書き込む前に「対象ファイル: 〈ファイル名〉(〈URL〉)で作業します。よろしいですか?」と1行で確認する**(別ファイルを操作する事故を防ぐため。以後の報告にもファイル名を添える)
3. `テンプレート`ページ直下の非表示テキスト `#config` を読む(figma-ops.md「#config を読む」)。オペレータには結果だけを短く伝え、中身は見せない
   - `skill_min_version` がこのスキルの版(上の「スキル版」)より新しい → **ここで止まる**。「このスキルは古い版です。リーダーに最新版への更新を頼んでください」とだけ伝える
   - `pipeline: "off"`、`#config` が見つからない、または読めない → `references/legacy-2026-08-20.md` の手順で進める(オペレータには「今回はこれまでの作り方で進めます」とだけ伝える)
   - `pipeline: "on"` → 以下の Step 1〜5
4. `制作物`ページに同じ案件のフレームがあり、その表紙直下に `#state` があれば、そこに書かれた Step から再開する(「前回の続きから再開します」と伝える。figma-ops.md「#state」)

## Step 1: ヒアリング

以下が揃うまでキャンバスに書き込まない。依頼文や会話・添付から拾えるものは先に埋めて「こう理解しました」と提示し、不足分だけを1回のメッセージで聞く。**着手できるかどうかは申告では決めず、Step 1.5 のゲートで確かめる**(「絵は準備できていますか?」とは聞かない)。

1. **案件情報** — 地域名・自治体/事業者名・サービス名称(「〇〇号」等の正式表記)。フレーム名・紙面の表記・素材ページの案件グループ名(`案件/<案件名>`)に使う
2. **作るもの** — 冊子(表紙+中面)か単票か。冊子の場合は「乗降スポットの一覧表は載せますか?」もあわせて確認
3. **載せる内容** — 文言の素材。なければ草案を作って確認を取る
4. **写真(実車・実風景)があれば** — 中面の信頼ブロック用。イラストはこちらで用意した絵を使うので持ち込まない(template-and-assets.md「素材の受け渡し」)
5. **色の指定** — 「自治体・事業者のブランドカラーなどの指定はありますか?」。なければ Step 1.5 で選ぶ絵の色で作る
6. **生成AIで作ったイラストを使ってよいか** — 「表紙の絵は画像生成AIで作ったものです。自治体・事業者の決まりで使えないことはありませんか?」。**使えない場合は Step 1.5 以降に進まず `references/legacy-2026-08-20.md` の手順で作る**
7. **地域名と名所の候補** — 表紙の山や川などの絵(地域の絵)に使う。リーダーが依頼文に書いていればそれを使う

## Step 1.5: 絵の系統と見本を選ぶ(色見本の選択の代わり)

1. **地域の絵の確認(ゲート)**: 素材ページに `案件/<案件名>` のグループがあり、その中に名前が `#地域モチーフ` で始まる絵があるかを確認する(figma-ops.md「地域の絵のゲート」)。**無ければ着手しない。**「この地域の絵がまだ準備されていません。共有チャンネルでデザイン担当に『〈案件名〉の地域の絵をお願いします』と依頼し、用意できたら『続きから』と声をかけてください」と伝えて止まる。他地域の絵では代用しない
2. **系統を選ぶ**: 表紙4系統(template-and-assets.md の表)のスクリーンショットを番号付きで見せて選んでもらう。事業者のブランド指定があれば MITT 系。**あわせて折り方を1行で確認する**: あいとま系・那智勝浦系・登別系は「下の段を逆さに組む折り方」、MITT 系は「下の段も上向きの折り方」。印刷の注文と違えば系統を選び直してもらう
3. **見本を選ぶ**: 選んだ系統の素材ページ `ライブラリ/<系統名>` のグループ(背景・人物・車両が並んだもの)のスクリーンショットを番号付きで見せる。注記「雰囲気の見本です。文字と細かい配置は変わります」を必ず添える
   - 見本が複数あるときは消去法で聞く(まず一番合わないものを外してもらい、残りから選ぶ)。見る観点は3つ: 「この絵の中にうちの地域の利用者がいると感じるか」「70代の親に渡して『いいね』と言われそうか」「うちの地域の地形と暮らし(山あい/海辺/町なか、農作業/買い物/通院)に近いか」
   - 見本が1つだけの系統(2026-10 時点は全系統1つ)は「この見本で進めてよいですか?」と聞く
   - 選んだ理由を一言もらい、そのまま記録する(言い換えない)
   - 「どれも違う」ときは最も近い見本で続け、共有チャンネルに一言報告してもらう
4. **色の指定がある場合**(Step 1 の5): 指定色を「メインの色」に充てる。MITT 系はブランド色が固定なので替えない(「MITT 系は色が決まっているため、指定の色は使えません」と伝える)。濃さの調整は figma-ops.md「指定色の反映」に従う

## Step 1.7: スタイルタイルで確認 → 記録

1. figma-ops.md「スタイルタイル」のスクリプトで、`制作物`ページの空き位置に `〈案件名〉_スタイルタイル_〈日付〉` を1枚作る(色チップ・実際のタイトルを見出しの書体で実寸・電話番号の見本・飾りの有無・表紙の絵の縮小を1枚にまとめたもの)
2. スクリーンショットを見せ、「この雰囲気で作ってよいですか?」と聞く。**見本側で決まっていない項目(標準の値を使っているもの)を1行で添える**(例: 「見出しの書体と構図は標準のものです」)。どれが標準かは記録の `provenance` が `default` の項目で分かる。オペレータへの質問は「はい/いいえ」だけにする
3. 「はい」→ 同じスクリプトが作った非表示の記録(`#tone` = 見た目の方針、`#state` = 進み具合)をタイルの中に残したまま Step 2 へ。「いいえ」→ どこが違うかを一言聞き、Step 1.5 の3からやり直す(不採用のタイルは消す)

## Step 2: テンプレート複製

1. Step 1.5 で選んだ系統の表紙+中面を**必ずセットで**複製し(乗降スポット表はヒアリング2で「あり」の場合のみ)、`制作物`ページへ移して `案件名_表紙/中面/スポット表_日付` に改名する(template-and-assets.md「複製の手順」。構図は K2 固定)
2. 複製直後に寸法が基準寸法と一致することを確認する
3. タイルの中の `#tone` と `#state` を**表紙フレームの直下へ移す**(非表示・ロックのまま)。`#state` の `step` を `"2"`、`frames` に複製したフレームの id を書く(figma-ops.md「#state」)。スタイルタイル本体は完了報告まで残す
4. 作業順序は **複製→色→見出し→文言→素材→装飾**(文言を入れた後の色替えは確認のやり直しになるため)

## Step 3: 組版(色・見出し・文言・素材・装飾)

**【H の結果待ち】** 変換表(計画書 D.2: 見た目の方針 → Figma 操作)に沿った自動組版は、くらぶちモックを手作業で1件通す検証(H(a) 先行版)の結果を見てから実装する。ここには次の順で入る予定:

- 色(メイン/淡い色の2群置換、電話・申込の色、差し色)/見出しの書体と2色/電話番号の書体
- 表紙の絵: `#キービジュアル`(背景、切り抜き配置)→ `#地域モチーフ` → `#車両` → `#人物`。**新しい図形は作らず、テンプレートに置いてある枠を差し替える**
- `#帯` `#背景` の表示と色、`#AI表記` の表示
- 中面は色の置換のみ(第1段)

それまでの暫定: 文言の差し替えは `references/legacy-2026-08-20.md` の Step 3 と同じやり方(1ブロックずつ、フォント読み込みの定型)で行い、改修で増えた枠(`#キービジュアル` など)には触らない。表紙の絵の組み込みはデザイン担当(モードD)が行う。

## Step 4: 自動チェック(第1層)と ○/✗ の要約

組版が終わったら、オペレータに聞かずに `references/preflight.md` のスクリプトを実行する(テンプレートページでは走らせない)。

1. 呼び出しの分け方: 表紙は1枚ずつ、中面は2枚まで、乗降スポット表は別の呼び出し。互いに独立なので同じメッセージで並べて出す
2. `CONFIG` で書き換えるのは次だけ:
   - `PAGE_ID` = `制作物`ページ、`FRAME_IDS` = 対象フレーム
   - `SHEET` = 冊子の表紙・中面は `'A3_booklet'`、乗降スポット表は `'A4_spot'`(このときは電話番号の大きさの項目は「対象外」になる)
   - `FRAME_KIND` = 表紙 `'cover'`、中面 `'inner'`(フレーム名に「表紙/中面」があれば `'auto'` のままでよい)
   - `FAMILY` = **Step 1.5 で選んだ系統から渡す**(`#tone` の `meta.template_family` を読み、あいとま系 → `'aitoma'`、那智勝浦系 → `'nachikatsuura'`、登別系 → `'noboribetsu'`、MITT 系 → `'MITT'`)。案件のフレーム名からは系統を推定できないため `'auto'` のままにしない
3. 返り値の `tmpRemovedAtEnd` が 0 であることを確認する(一時的に作った計測用の複製が残っていない証拠)
4. オペレータには**チェック項目ごとに1行の ○/✗/△ だけ**を見せる。書き方は preflight.md §6「○/✗/△ 要約の作り方」に従い、複数フレームの結果は項目ごとにまとめる。項目名はやさしい言葉にする(P1 寸法 / P2 文字の大きさ / P3-a 文字のはみ出し / P4 文字と背景の見やすさ / P6 折り目との距離 / P7 仮の文言 / P12 電話番号の大きさ)。△ は「次回改善(このまま印刷に出せます)」または「目で確認」と添える。`寸法` が ✗ のときは他を読まずに「寸法が違うので複製からやり直します」を先に出し、Step 2 からやり直す
5. `#state` の `preflight` に結果の要約(フレームごとの fail/warn/manual の件数と実行日時)を書く
6. ✗ の自動修正: **【H の結果待ち】** 自動修正2回(何をどう直すか・直したあとの再チェック)は H(a) 先行版の結果から決める。それまでは ✗ を直さず、Step 5 の残指摘に回す

## Step 5: 手作業への引き渡し

**【H の結果待ち】** 書き出し用の枠(塗り足し付きラッパー)の自動作成と縮小(計画書 D.3)は H(a) 先行版の結果から実装する。それまでは書き出しをデザイン担当が行う。

終了時に必ず伝える:

- 作成・変更したフレーム名と場所(スタイルタイルは不要になったら削除してよいか確認する)
- Step 4 の ✗・△ の残り(残指摘)と、未完了・要確認の箇所(仮置き文言、未確認の電話番号・QR等)
- **✗ が1つでも残るときは「このままでは印刷に出せません」と明記し、書き出すファイル名の末尾に `_未確認` を付けるよう伝える**(入稿しない。リーダーが直してチェックをやり直し、✗ が 0 になってから入稿する)
- 表紙の絵(生成AI)を使ったときは、`#AI表記` が表示されていることを確認する
- Figma上で自分で微調整するヒント(例:「文字はダブルクリックで直接編集できます」)

`#state` の `step` を `"5"` にする。
