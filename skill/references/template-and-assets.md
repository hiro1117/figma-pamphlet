### 複製の手順

1. 対象フレームを clone し、`制作物`ページへ移す(`const p = await figma.getNodeByIdAsync('7:2'); await figma.setCurrentPageAsync(p); const c = (await figma.getNodeByIdAsync(ID)).clone(); p.appendChild(c);`)→ 既存フレームと重ならない空き位置(右端の右 200px)に配置 → `案件名_表紙/中面/スポット表_日付` に改名する
2. 複製直後に width/height が基準寸法と一致することを確認する(回転は引き継がれる。あいとま系表紙は 180°、スポット表は 90°)
3. マスター本体・参照ページは編集しない

## 面と折り線(A3・6面)

- シート A3(297×420mm)= 作業寸法 1691×2392px。横半分に折ってから巻き三つ折り → 片面 3列×2段 = 6面、1面 563.7×1196px = 99×210mm
- **k = 1691 / 297 = 5.69 px/mm**(1pt = 2.01px、3mm = 17px、5mm = 28px、8mm = 46px、12pt = 24px、10pt = 20px、9pt = 18px、2cm = 114px)。しきい値は必ず k から計算する(旧計画の A4 / k=8.05 は誤り)。乗降スポット表は A4 で k = 794 / 210 = 3.78

## `#` 命名規約

凡例フレーム 599:2(テンプレートページ)の規約に合わせる。

- `#` で始まる = 差し替えてよい。`#<役割>:<スロット名>` の形(例 `#見出し:キャッチコピー` `#本文:利用シーン1` `#電話:メイン` `#CTA:パネル` `#注記:受付時間`)。スキルは役割(`name.startsWith('#見出し')`)で拾い、スロット名で文言を当てる
- 役割の一覧: 文字 `#見出し` `#本文` `#注記` `#電話` `#CTA` `#バッジ` / イラスト `#キービジュアル` `#人物` `#車両` `#地域モチーフ` / 飾り `#帯`(中に `装飾:帯背景` と `#帯文言`)`#背景` / 管理 `#tone` `#state` `#config`(非表示)/ 素材ページ `#案_透かし有`
- 既存の `#〇〇置き場`(灰 #E6E6E6 + 破線 #999999 の枠)はそのまま。`#QR置き場` が `#QR` を兼ねる
- `#` の無い接頭辞(凡例): `面:` `ブロック:` `行:` `装飾:` `ラベル:` `見出し:` `イラスト:` `固定画像:` `サンプル:`(見本文言。仮置きチェックの対象外)`ガイド:`(折り目チェックの対象外)
- 表4側(逆さ面・MITT の使い方面(下))は改修で改名していない。旧名(`#電話番号(予約)` 等)のまま
- 2026-09-27 の表紙面の `#` 枠一覧とノード id: リポジトリ `docs/prep/template-refit-inventory.json`

## 装飾の配置規則(折り目・塗り足し)

1. **文字は表紙・中面とも折り線(縦2本・横1本)から 46px(8mm)以上離す**(第1段の自動チェックは面境界で 5mm 未満を ✗、8mm 未満を △)
2. 飾りは表紙フレームでは面ごとに完結させ、折り線 ±17px(3mm)に置かない。中面では背景・イラストの折り目またぎを許す
3. 折り線 ±17px に濃い色のベタ(相対輝度 0.2 未満)を置かない(背割れ)
4. 飾りの辺は「仕上がり端から 17px 以上内側」か「17px 以上外側まで延長」のどちらか(端にぴったり揃えない)
5. 帯の中の文字は帯と一緒に回し、8文字以内。本文・電話番号・QR の説明は絶対に傾けない
6. 背景は既定で平塗り。グラデーションは `#tone` で指定された場合のみ
7. 1つの文字に効果(フチ・影・グラデ)は1種まで。1面の飾りは3種まで

## フォント許可リスト

Figma 上の**正確なファミリ名**で `loadFontAsync` する(名前違いは読み込みに失敗する)。

- 本文・注記・固有名詞(地名・サービス名・電話番号): **`Noto Sans JP` / `BIZ UDPGothic` のみ**
- 見出し(`#見出し` 系): 上記に加えて `BIZ UDGothic` / `Zen Maru Gothic` / `Zen Kaku Gothic New` / `M PLUS 1p` / **`Rounded Mplus 1c`**(Thin〜Black)と **`Rounded Mplus 1c Bold`**(Bold のみ、別ファミリ名)。Google Fonts の "M PLUS Rounded 1c" は Figma ではこの名前で、`M PLUS Rounded 1c` では読めない
- 装飾用(現行テンプレで使用中。**数字・欧文・記号の飾りだけ**に使い、和文の本文には使わない): `Baloo Paaji`(料金・数字)/ `Yusei Magic`(MITT 系表紙の見出し)/ `Titan One`(スポット番号)
- フォールバック: 見出し → `Noto Sans JP` Black、本文 → `BIZ UDPGothic`(または同ウェイトの `Noto Sans JP`)
- テンプレに残っている環境外フォント(`Source Han Sans JP` Medium/Bold、`Hiragino Kaku Gothic Pro` W6、`ADS-piccolo`)は、各 PC にインストールして解消する方針(置換しない)。入っていない PC では文字のはみ出しチェックが「目で確認」になる
- 見出しの書体を替えたら、get_screenshot で欠字・書体の混ざりを目視する

## 差し替えの約束事

- 差し替え対象は、テンプレートで**空欄・仮置きになっているテキスト**と `#` の枠。文言・画像を入れるだけにし、固定区分(本文のフォント・サイズ・罫線・レイアウト)は変えない
- 未確定の電話番号・日付等は「(仮)」を付けて入れる(自動チェックの「仮の文言」で ✗ になり、引き渡しで気付ける)

## カラーの適用(濃淡2群置換)

`pipeline: on` では色は `#tone` の役割から決まり、`scripts/recolor.js` がこの表の色を置き換える: あいとま `#EB6EA5 → main`・`#F6BED1 → main_tint`・`#FFD8E3 → ground` / 那智勝浦 `#1B98D0 → main`・`#76C1E3 → main_tint` / 登別 `#D7835F → main` / MITT 替えない / スポット表 `#EB6EA5`・`#DE4891 → main`。加えて表紙面の電話番号の文字と CTA 見出しのメイン色の部分、白い文字が載るメイン色のパネル・帯(1面の 20% 以下)を `cta` に。`#バッジ` は替えない(B.1 v2 の Hiro 判断)。`pipeline: off`(旧手順)ではこの節の以下の手順どおり。


テンプレートの配色は「メイン色の濃トーン(見出し帯・枠・強調)+淡トーン(背景面)+紙の白」で構成されている。案件の色に替える手順:

1. ヒアリングで確認したメイン色を濃トーンに充てる。アクセントは指定があった場合のみ置換
2. 淡トーンはメイン色から自動導出する(同色相で明度を上げ彩度を落とす。目安: HSLでL+25〜35・S−20〜30)
3. 置換は2グループ一括で行う: 下表の濃トーン群→新メイン色、淡トーン群→新淡色。**黒系(#000000 / #231815 / #1D1715 = 文字・イラスト線)と白・グレーは触らない**

| 系統 | 濃トーン | 淡トーン | 備考 |
|---|---|---|---|
| あいとま系 | #EB6EA5 | #F6BED1, #FFD8E3 | |
| 那智勝浦系 | #1B98D0 | #76C1E3 | アクセント黄 #FAEF50 は指定時のみ置換 |
| 登別系 | #D7835F | (白ベース・淡なし) | |
| MITT系 | #254F99, #143747 | #258FC2ほか | **ブランド固定色。原則色替えしない** |
| 乗降スポット表 | #EB6EA5, #DE4891 | — | 複製後、案件の濃色に合わせる |

4. 置換後にget_screenshotで反映漏れを目視確認する(表と微妙に違う近似色の直塗りが残っていたら個別に直す)
5. **画像化された装飾・イラスト(IMAGE fill)には色置換が効かない。** SVGでの自作差し替えは品質が保てないため行わない。基本はそのまま残し、案件カラーと合わず色味の調整が必要な箇所は、Step 5の引き渡し時に「イラストの色味調整」として残タスクに含めて報告する(色味の調整は作業者が手作業で行う運用)

### カラー未定時の提案

1. 題材・地域のイメージから2〜3案を選定する(例: 海沿いの町→青系、温泉地→暖色系、公的な信頼感→紺系)
2. `制作物`ページの隅に、案ごとの濃淡チップ+案名を並べたカラー見本フレームを生成する
3. スクリーンショットで見せて選んでもらう。RGB値の口頭提示はしない(非エンジニアには選べない)
4. 決定後、不採用案の見本フレームは削除する

## 素材の受け渡し

`pipeline: on` では、**イラストはライブラリ(素材ページ `ライブラリ/<系統>` と `案件/<案件名>`)の絵だけを使う**(1紙面1ソース。持ち込みイラストと混ぜない)。持ち込みは**写真(実車・実風景)に限り**、中面の信頼ブロックに使う。写真の受け取り方は下の基本フローと同じで、置き場所は `案件/<案件名>` のグループ。持ち込みイラストがどうしても必要な案件は「写真に差し替える」か「旧手順(`pipeline: off` と同じ作り方)で作る」かを確認する。

以下は旧手順(と写真の受け取り)の説明。

### イラスト・写真の受け渡し(旧手順)

利用者が商用利用可のサイトで選び、Figmaに取り込む。案内は平易な文で伝える。

**基本フロー(確実に動く):**

1. 利用者が素材をダウンロードし、`素材`ページに**案件名のグループ(またはフレーム)を作ってその中に**置く
2. 利用者からそのグループのURLを受け取る。URLの`node-id`(例: `?node-id=12-34` → ノードID `12:34`)でグループを特定する。URLがもらえない場合はグループ名(案件名)を聞き、名前で特定する
3. **対象はそのグループ内の画像のみ。素材ページ全体を走査しない**(過去案件の素材が溜まっており、どれを使うか判別できないため)。グループ内の画像を数えて点数を報告し、**全点の配置先を決めた計画**(どのイラストを紙面のどこに使うか)を提示する
4. 計画に沿って、cloneでパンフの所定位置に複製・配置・リサイズする。グループ内の元画像は残す(再利用のため)

案内文の例: 「選んだイラストを、Figmaの『素材』ページに今回の案件名でグループ(枠)を作って、その中にドラッグ&ドロップで入れてください。入れ終わったら、そのグループを選択して右クリック→『選択部分へのリンクをコピー』でリンクをコピーして、ここに貼ってください」

**全点使用の原則:** 案件グループに入っているイラストは、利用者が選んで持ってきた素材なので**すべて配置するのが前提**。イラスト置き場が足りなければ、ブロックの脇・背景・余白のワンポイントとして追加配置してよい(可読性基準は守る)。紙面に収まらない・トーンが合わない等で使い残す場合は、勝手に間引かず「〇〇は△△の理由で外しますが良いですか」と確認を取る。

**チャットに画像が添付された場合:** upload_assetsでの取り込みを試し、失敗したら基本フローを案内する。

**既存テンプレートのイラスト流用(オプション):** 利用者の指示があれば、テンプレート・参照ページにある既存イラストをcloneして配置してよい(マスター・参照の原本は変更しない)。案件カラーと色味が合わない場合もClaudeは色をいじらず配置のみ行い、色味調整は残タスクとして引き渡す。

### ライセンス確認(素材を受け取るたび)

どのサイトの素材かを確認し、以下を利用者と確認する。最終判断はせず「規約のこの点を確認してください」と指摘に留める。

- 商用利用の可否 / クレジット表記の要否(必要なら発行者情報欄へ) / 加工の可否 / 1制作物あたりの点数制限
- 出所不明の画像は配布物に使わない

## 入稿データの厳守(最重要)

このファイルの制作物はそのまま**印刷入稿用データ**になる。寸法がズレると折り畳んだ際に折り山の印刷がズレるため:

- 基準寸法(参照ページの本データと同一): 冊子の表紙・中面 = **1691×2392**(那智勝浦系の中面のみ横型 **2392×1691**)、乗降スポット表 = **794×1123**
- **フレームのresize・面境界の移動は絶対にしない。** 複製は原寸のまま行い、複製直後にwidth/heightが基準寸法と一致することを確認する
- 折り位置をまたぐ要素・接する要素の位置は動かさない。動かす必要が出たら手作業に引き渡す
- 背景・裁ち落とし要素は塗り足し(仕上がり端の 17px 外)まで伸ばし、文字は仕上がり端・折り位置から余裕を持って内側に置く。制作物フレームは clipsContent=false のまま
- トンボはデータ内に描かない

### 入稿 PDF の3つの寸法

Figma の PDF 書き出しは 1px = 1pt・1倍のみ。1691×2392 をそのまま書き出すと 596.5×843.8mm・塗り足しなしになるため、書き出し用の枠(ラッパー)を経由する。

| 層 | 寸法 | 作り方 |
|---|---|---|
| 作業寸法 | 1691×2392px = A3 297×420mm | テンプレのまま。resize 禁止 |
| ラッパー(縮小前) | **1725.2×2426.2px**(四辺 +17.08px = 3mm) | `書き出し`ページの空フレーム(clipsContent=true、塗り = 端の色の多数派)に、制作物フレームの複製(clipsContent=false、回転は保つ)を (17.08, 17.08) に入れる |
| ラッパー(縮小後) | **858.9×1207.9px = 303×426mm**(1px=1pt) | ラッパーに `rescale(0.497865)`(= 841.89 / 1691。A3 短辺 pt ÷ 作業 px)。中の複製も同率で縮み、位置は (8.5, 8.5) |
| 入稿寸法 | 303×426mm(トンボなし) | 縮小後のラッパーを選んで Export(PDF、画質 High) |

- 案件ごとに表紙ラッパー・中面ラッパーの2枚(`案件名_表紙_書き出し_日付` / `案件名_中面_書き出し_日付`)。既定は2ファイル(印刷会社の指定があればそちら)
- 既定は sRGB のまま PDF。CMYK 必須の印刷会社のみデザイン担当が変換する
- 12pt 未満の文字は #000000(黒)に統一してある。広い黒ベタは使わない
- ラッパーの作成・縮小は Step 5 で `scripts/wrapper.js` が行う。**塗り足しは端の色の延長**(辺ごとに端の色を調べ、一番長い色をラッパーの塗りに、それ以外の区間は背面に `塗り足し:<辺> <区間>` の帯を置く。端が写真・グラデーションの区間は `unknown` として返るので手作業)。オペレータが行うのは Export だけ
