# 表紙の絵の材料(`illustration`)

表紙の絵は、系統ごとの背景・人物・車両(ライブラリ)と、案件ごとの `#地域モチーフ` を重ねて作る(figma-pamphlet `references/keyvisual.md`)。依頼票はその**材料**を残す。画像は作らない。ここで書いた材料は、あとで画像生成(Nano Banana など)のプロンプトの「必須要素」に差し込む。

## 1. 形

```text
illustration
  vehicles[]
    label_in_source  Fact  資料の表記そのまま(「セダンまたはジャンボタクシー」)
    class            下の §2 の分類(資料が「AまたはB」なら A・B を別の要素に分けて2件にする)
    seats            Fact  定員(乗客)
    count            Fact  台数(資料にあれば)
    operator         Fact  使う事業者
    body_color       Fact  車体色。資料にまず無い → 要確認
    roof_sign        Fact  行灯の有無・色
    livery           Fact  ラッピング・ロゴ・ステッカー(「なし」も確定値)
    accessible       Fact  車いす対応・スロープ・リフト
  cover_pick         { class, status, reason }  表紙に描く1台の提案
  library_fit        { status, note }  既存ライブラリの車両がそのまま使えるか(§2 の最後)
  region
    terrain[]        Fact  地形(海沿い/島/山あい/丘陵/田園/ため池/川沿い/町なか/温泉地)。エリアごとに違えば area を付ける
    lifestyle[]      Fact  暮らし(買い物・通院・通学・駅への乗り継ぎ・農作業)
    destinations[]   Fact  資料に出てくる行き先(店・駅・病院・中心部)。絵には看板・店名を描かない
    landmarks[]      { name, kind, area, status, reason, caution }  地域モチーフの候補
    avoid[]          描かないもの(理由付き)
  riders[]           { who, activity, where, status }  利用者像 1〜2人
  season             Fact  配布時期から見た季節(秋配布なら紅葉・稲刈りは可、桜は避ける など)
  prompt_seed        { vehicle, region_motif, riders }  §4 の組み立て結果(日本語)
```

## 2. 車両の分類

資料の言い方はばらばら。見た目(シルエット)で分ける。**プロンプトには車名・メーカー名を入れない**(メーカーに似せない決まり。資料の表記は `label_in_source` にだけ残す)。

| class | 資料での言い方の例 | 乗客の目安 | 絵の特徴(プロンプトに使う言い方) |
|---|---|---|---|
| `sedan` | セダン、普通車タクシー、小型・中型タクシー | 4 | 低い4ドアの箱型セダン、トランクあり、屋根に小さな行灯 |
| `tall_taxi` | JPN タクシー型、UD タクシー、ユニバーサルデザインタクシー | 4〜5 | 背の高い丸みのあるワゴン型、後ろはスライドドア、屋根に行灯 |
| `minivan` | ワゴン、ミニバン、7人乗り | 6〜7 | 丸みのあるミニバン、大きな窓、横のスライドドア |
| `jumbo` | ジャンボタクシー、ワンボックス、10人乗り、ハイエース、キャラバン | 9〜10 | 四角いワンボックス、平らな顔、高い屋根、横のスライドドア、窓が3列 |
| `microbus` | マイクロバス、コミュニティバス、小型バス | 11〜29 | 小型のバス、前の扉、窓が並ぶ |
| `kei` | 軽自動車、軽ワゴン | 3 | 小さく背の高い軽ワゴン |
| `unknown` | 記載なし・「車両は事業者の保有車両」 | — | 要確認 |

- 「AまたはB」は両方を `vehicles[]` に入れる。定員が「1便8名まで」のように書かれ、超過時に「セダン3台」などとあれば、その運用も `note` に残す(どちらが普段の車両かの判断材料)
- **`cover_pick` の決め方**: 住民がいちばんよく見る車両。資料で決まらなければ `status: "推測"` で提案し、`open_questions` に「ふだん走るのはどちらですか?」を入れる。迷ったら「乗合」らしく見える大きい方(複数人が乗れる形)を提案する
- **`library_fit`**: ライブラリ v0 の車両は4系統とも「白いミニバン/背の高いタクシー型・スライドドア・行灯はアクセント色」(keyvisual.md §3 の前景の固定仕様)。`cover_pick` が `minivan` `tall_taxi` なら `"使える"`、`sedan` `jumbo` など形が違えば `"作り直しが要る"` とし、デザイン担当への依頼事項として `note` に書く(ブロックはしない)
- 車体色が分からないときの既定は「白」(ライブラリと同じ)。ただし事業者の車が黒・黄などで住民がその色で覚えているなら合わせたほうがよいので、聞き返しに入れる

## 3. 地域の絵(`region`)

1. **地形**: 運行区域の町名から。海に面した町・島・山の名が付く町・ため池の多い平野など。一般知識からの判断なので `推測` でよい(町名という根拠は `reason` に)
2. **暮らし・行き先**: 資料の時刻表の発地・行き先・乗り継ぎ先(「〇〇店発」「中心部発」「駅で路線バスに乗り継ぎ」)は `確定`
3. **名所の候補(`landmarks`)**: 2〜4個。選ぶ基準は次の順
   - 運行区域の中にある、または区域から見える
   - 住民が「うちの町だ」と分かる形(山・橋・島・川・海岸線などシルエットで分かるもの)
   - 1点で描ける(地平線の帯 横長 488×143 程度に収まる)
   - 所在が行政境界にまたがるもの・区域外のものは `caution` に書く
4. **描かないもの(`avoid`)**: 実在の店舗・病院の建物と看板、特定の寺社を大きく(宗教色)、富士山+桜+鳥居の組み合わせ、季節外れのモチーフ、ほかの自治体の象徴

## 4. プロンプトの種(`prompt_seed`)

keyvisual.md §3 の「必須要素」にそのまま差し込める日本語の1〜3文にする。描法・色・制約は系統と tone で決まるので**ここには書かない**。

- 車両: 「乗合タクシーの車両1台。〈§2 の絵の特徴〉。日本仕様の右ハンドル・左側通行。斜め前(車の左前が見える向き)から見た全体像。車体は〈車体色〉、屋根に小さな行灯(文字なし)。ナンバープレートは無地。ロゴ・文字・電話番号・ラッピング模様なし。」
- 地域モチーフ: 「〈地名〉の〈名所〉のシルエット(〈形の特徴: 例 ゆるやかな台形の山並み/長い吊り橋と島影〉)。横長の帯に収まる1点。建物の看板・文字なし。」
- 利用者: 「〈年代・性別の幅〉の住民が〈行動: 例 買い物袋を持って乗り込む/電話で予約する〉。顔のある人物、杖・着物・白髪だけで高齢者を表さない。」

形の特徴が一般知識で言えないとき(実物を知らない名所)は、`prompt_seed.region_motif` を `null` にし、「写真か地図の提供をお願いします」を聞き返しに入れる。
